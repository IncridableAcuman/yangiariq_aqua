## 1. High-Level Production Architecture

YANGIARIQ AQUA AI operates as an edge-gateway-secured, containerized modular monolith with strict internal network isolation. All external traffic terminates at NGINX over TLS/HTTPS, while application and persistence services reside on an unexposed internal bridge network.

## 2. Key Architectural Invariants

1. **Zero Public Exposure of Persistence:** Neither PostgreSQL (`5432`) nor internal backend services (`8080`) bind to the public host interface. Only NGINX binds to host ports `80` and `443`.
2. **Reverse Proxy Forwarding Strategy:** The Spring Boot backend uses `server.forward-headers-strategy: framework` to securely interpret `X-Forwarded-For`, `X-Forwarded-Proto`, and `X-Forwarded-Host` generated by NGINX, preventing header injection and client IP spoofing.
3. **Internal Actuator Isolation:** Spring Boot Actuator endpoints (`/actuator/**`) are never routed through public NGINX location blocks. They are exclusively accessible from the internal Docker network for container healthchecks and internal metric scrapers (Prometheus).
4. **Defense-in-Depth Rate Limiting:**
   - **Edge Layer:** NGINX buffers and controls burst connections.
   - **Application Layer:** `RateLimitingFilter` applies strict sliding-window IP limits to sensitive authentication paths (`/api/v1/auth/login`, `/refresh`, `/register`, `/password-reset/**`), returning standard RFC 6585 `429 Too Many Requests` responses with `Retry-After: 60`.
5. **Fail-Fast Production Invariants:** `ProductionSecurityValidator` prevents the Spring Boot application from booting in `prod` profile if default development credentials, short JWT keys (<256 bit), or localhost CORS configurations are detected.

## 5. Security & Isolation Boundaries

- **Container Privileges:** The Spring Boot backend runs under an unprivileged user `aqua:aqua` (UID/GID created in alpine runtime stage). Root execution is forbidden.
- **Resource Constraints:** Every container is assigned explicit `deploy.resources.limits` (CPU and Memory) in `docker-compose.prod.yml` to prevent runaway memory leaks or CPU starvation from impacting the host OS.
- **Logging Governance:** Containers use Docker's `json-file` log driver with rotating log file limits (`max-size: 10m`, `max-file: 3`), ensuring log files cannot exhaust server disk space.
- **Zero Actuation Guarantee:** The architecture contains zero hardware controllers, zero physical actuator modules, and zero automated gate switches.
