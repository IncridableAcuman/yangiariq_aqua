Every prediction generated in YANGIARIQ AQUA AI is traceable to the exact method version and parameter snapshot that produced it.

## 2. Database Schema Traceability

The `predictions` table contains dedicated immutable audit columns:

```sql
ALTER TABLE predictions ADD COLUMN method_version_tag VARCHAR(64);
ALTER TABLE predictions ADD COLUMN configuration_snapshot TEXT;
CREATE INDEX idx_predictions_version_tag ON predictions(method_version_tag);
```

When predictions are evaluated retrospectively:
- `PredictionOutcomeMatcher.resolveModelVersion(Prediction)` reads `prediction.getMethodVersionTag()`.
- Historical predictions generated by `V1` evaluate against `V1` metrics even if `V2` is later deployed.
- Historical data is never contaminated or re-tagged.

---

## 3. Strict Immutability Guarantees

Once a prediction method version is approved and transitioned into `ACTIVE` production:
1. `PredictionMethodVersion.markImmutable()` sets `isImmutable = true`.
2. Any subsequent invocation of `updateConfiguration(newConfig)` immediately throws:
   ```java
   throw new IllegalStateException("Cannot modify immutable prediction method version: " + versionTag);
   ```
3. When calibration is proposed, the system creates candidate `V2`, leaving `V1` intact.
4. If an operator triggers an emergency rollback, `V1` is re-activated without altering its configuration snapshot.

This guarantee ensures 100% reproducibility across all post-irrigation audits, regulatory inquiries, and water accounting verifications.
